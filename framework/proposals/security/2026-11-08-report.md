# security — legislative report for 2026-11-08

## What I observed
During the audit period 2026-11-08 the following patterns were observed:
- CI pipelines in the build stage were granted read access to the entire secret vault, allowing jobs to retrieve secrets they never declared a need for.
- Service accounts deployed in development environments were bound to the broad "editor" IAM role, giving them write access to resources unrelated to their function.
- Administrative SSH keys were stored in a shared secret namespace that is readable by all engineering staff, exposing host-level access beyond the principle of least privilege.
These observations indicate that access scopes are broader than necessary and that secret handling does not enforce explicit declaration or short‑lived usage.

## Open risks
- CI pipelines can exfiltrate any secret, increasing risk of credential leakage.
- Over‑privileged service accounts can modify or delete unrelated resources, expanding attack surface.
- Shared admin secrets expose host access to a wide set of users, violating least‑privilege principles.
