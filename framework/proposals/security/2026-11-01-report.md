# security — legislative report for 2026-11-01

## What I observed
During the review period several privilege‑escalation vectors were identified: developers hold broad Owner‑level IAM roles granting unrestricted access to compute, storage, networking and secret stores; CI pipelines possess a wildcard read permission on the entire secret store and can retrieve any secret regardless of need; service account keys are generated without expiry and remain valid indefinitely; and the secret management system lacks namespace isolation, allowing any application with read rights to enumerate all secrets. These patterns violate the principle of least privilege and increase the attack surface.

## Open risks
- Developers with Owner‑level IAM roles can modify any resource, exposing the environment to accidental or malicious changes.
- CI pipelines can read all secrets, potentially leaking credentials unrelated to a given job.
- Long‑lived service account keys provide persistent authentication tokens that can be exfiltrated and used indefinitely.
- Flat secret storage permits cross‑application secret access, increasing data leakage risk.
