# reliability — legislative report for 2026-11-22

## What I observed
During the reporting period several recurring safety gaps were identified:
1. Two incidents where members of a redundant pair of database nodes were modified in the same deployment window, violating the redundant‑pair change safety rule.
2. A medium‑risk restart of the payment‑gateway service was performed without an approved rollback plan, leading to a brief outage.
3. Multiple alerts for missing latency monitoring on the user‑profile service, leaving no visibility on latency spikes.
4. A change to the shared configuration store was applied without cross‑team approval, creating a configuration drift that later caused a cascade failure.
These patterns indicate weak enforcement of dual‑owner approval, insufficient post‑change health checks for critical services, and gaps in monitoring coverage for latency‑sensitive components.

## Open risks
- Redundant pair changes performed without dual‑owner sign‑off, risking simultaneous failure.
- Critical service restarts lacking documented rollback procedures, increasing outage risk.
- Missing latency alerts for latency‑sensitive services, reducing incident detection speed.
- Unapproved changes to shared configuration stores causing configuration drift.
